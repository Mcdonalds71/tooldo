# ADR 0005 — Move to Astro 7 before building the tools

## Status
Accepted.

## Context
The project scaffolded on Astro 5.18.2. `pnpm audit` reports two high advisories against
that line: reflected XSS through an unescaped slot name (patched in 6.3.3) and a Host
header SSRF in the prerendered error page fetch (patched in 6.4.6). A third, inherited
libvips CVEs via the `sharp` that Astro pulls in, clears with the same bump.

Neither Astro advisory describes a reachable path in this site. Both live in the server
surface, and the output is fully static — no adapter, no runtime, no dynamic slot names.
The `sharp` issues are build-time only, on image inputs that come from the repo.

That makes the upgrade a question of cost and timing rather than exposure. Right now the
codebase is four pages, a design system and no tools. The cost is only ever going up: the
architecture puts ten engines and ten islands ahead of us, and a major framework bump
across that surface is a different kind of week. A red audit check on a public portfolio
repo also reads as neglect regardless of whether the finding is reachable.

`docs/build-spec.md` names Astro 5, so moving lines needs a decision recorded rather than
a quiet dependency bump.

## Decision
Upgrade to Astro 7.1.6 with `@astrojs/react` 6.0.2, in one change, before the first tool
is built.

## Consequences
- `pnpm audit --audit-level high` reports nothing, so CI is honest again.
- Nothing in the source needed changing. Typecheck across 53 files, 57 unit tests, the
  build, and all 24 Playwright smoke tests pass untouched — the config API, island
  directives and Tailwind Vite plugin all carried over as written.
- React 19 stays; `@astrojs/react` 6 peers it directly.
- The stack section of `docs/build-spec.md` and `CLAUDE.md` now say Astro 7.
- Doing this before tool #1 means every engine and island is written against the current
  major from its first commit, rather than being migrated later.
- TypeScript 5 → 7 is a separate decision, deliberately not bundled here. It replaces the
  compiler implementation, and a type-system change tangled up with a framework change
  makes any regression twice as expensive to attribute.
